# 医院路径：到终点的完整路线与表单填写

> 适用：`Ruby/hospital-pathway-zh-learn`（中文界面）或正式版 `Coursework/hospital-pathway`（英文界面，选项含义相同）。  
> Tasklist 认领人：`demo`。病例号建议全程统一，例如 `DEMO-001`。

---

## 1. 终点一览（一共 8 个）

| 终点（英文） | 中文含义 | 典型怎么走到 |
|--------------|----------|--------------|
| `Enquiry resolved`（Admin） | 行政问询结束 | 登记选「行政问询」→ P10 |
| `Enquiry resolved`（Clinical） | 临床问询结束 | 登记选「临床问询」→ P10 |
| `Enquiry resolved`（Finance） | 财务问询结束 | 登记选「财务问询」→ P10 |
| `Report reviewed` | 报告审阅结束 | 登记选「管理审计/报告」→ P13 |
| `Referral rejected` | 转诊驳回 | 主路径转诊审阅选「驳回」 |
| `Referral closed` | 转诊关闭（转科） | 转诊审阅选「转科」 |
| `Care episode ended` | 本段诊疗结束 | 主护理路径出院，或变更后出院 |

## 2. 第一步：登记表决定走哪条线（P1 / P10 / P13）

表单：`register_request`（登记申请）

| 申请类型（界面文字） | 内部值 | 下一任务 | 覆盖业务 |
|----------------------|--------|----------|----------|
| 新转诊 - 材料已核验 | `referral` | P2 顾问审阅转诊 | 主路径入口 |
| 转诊 - 支持材料缺失 | `referral_incomplete` | P1/P11 补材料 → 再回登记 | 材料补齐环 |
| 行政问询 | `enquiry_admin` | **P10 处理行政问询** | 短线终点 |
| 临床问询 | `enquiry_clinical` | **P10 临床答复问询** | 短线终点 |
| 财务问询 | `enquiry_finance` | **P10 财务答复问询** | 短线终点 |
| 授权变更 / 随访 / 取消 | `change` | P11/P12 临床变更 | 变更线 |
| 管理审计 / 报告 | `report` | **P13 审阅审计与报告** | 短线终点 |

公用填写：

- 患者 / 病例编号：`DEMO-001`（自定即可）
- 专科、优先级、备注：演示随便填（必填项填满）

## 5. ★ 推荐完整体验：主路径 + 两个 Java → `Care episode ended`

覆盖：P1→P2→P3/P4→P5/P9→P7（Java 支付）→P6（Java 预约确认）→再临床→出院。

病例号建议：`DEMO-JAVA-01`

| 顺序 | 阶段 | 任务（P） | 表单 | 关键选项 / 填写 |
|------|------|-----------|------|------------------|
| 1 | 入口 | P1/P10/P13 登记 | `register_request` | 类型 = **新转诊 - 材料已核验** |
| 2 | 转诊 | P2 顾问审阅 | `review_referral` | 决定 = **接受** |
| 3 | 就诊 | P3/P4/P12 预约就诊 | `book_visit` | 结果 = **已预约、通知且已到诊** |
| 4 | 临床 | P5/P9/P12 临床护理 | `clinical_care` | 结果 = **授权治疗 / 下一疗程**（必须选治疗，后面才能进经费） |
| 5 | 信件 | P9 寄送门诊信件 | `dispatch_letter` | 结果 = **已批准信件已寄出并记录** |
| 6 | 经费 | P7 经费评估 | `funding_assessment` | 结果 = **需要患者付费 - 调用支付方**；金额 = **`10.01`** |
| 6b | Java① | P7 向外部发起支付 | （无表单，自动） | 控制台：`request-payment SUCCESS` |
| 7 | 治疗预约 | P6 确认治疗预约 | `book_treatment` | 结果 = **资源可用；预约已确认** |
| 7b | Java② | P6 发送预约确认 | （无表单，自动） | 控制台：`send-booking-confirmation` |
| 8 | 临床再入 | P5/P9/P12 临床护理 | `clinical_care` | 结果 = **授权出院 / 无需继续护理** |
| 9 | 信件 | P9 寄送门诊信件 | `dispatch_letter` | 结果 = **已批准信件已寄出并记录** |
| — | **终点** | `Care episode ended` | — | 本段诊疗结束 |

说明：

- 金额 `10.01` → 支付成功；`10.00` → 失败，进 P7「处理经费问题」，到不了 Java②。
- 第 4 步若选「随访」会回到预约就诊，不会进经费/Java。
- 登记后 `urgentCase=false`，紧急财务「是否跟进」默认走「否」，不会插 P8。

## 6. 主路径变体（仍到 `Care episode ended`，但不强制 Java）

公共：登记转诊 → 接受 → 已到诊 → 临床选**治疗** → 信件已寄出 → 进入经费。

### 6.1 医院经费（不调支付 Worker）

| 任务 | 怎么填 |
|------|--------|
| P7 经费评估 | **医院经费已确认**（或保险批准 / 已核验支付 / 豁免安排） |
| P6 确认治疗预约 | **资源可用** → 仍会跑 Java② 预约确认 |
| 再临床 | **出院** → 信件已寄出 → 终点 |

> 只有选「需要患者付费」才会跑 Java①；Java② 在「资源可用」时仍会跑。

### 6.2 支付失败再成功（体验 P7 问题处理）

| 顺序 | 任务 | 怎么填 |
|------|------|--------|
| …到经费 | P7 经费评估 | 患者付费；金额 **`10.00`** |
| Java① 失败 | — | 日志 `UNSUCCESSFUL` |
| P7 处理经费问题 | `simple_record` | 已完成并记录 |
| 回 P7 经费评估 | | 再选患者付费；金额 **`10.01`** |
| 之后同推荐路线 | | 预约 ready → Java② → 出院 |

### 6.3 第一次就诊就出院（最短护理终点，无 Java）

| 顺序 | 任务 | 怎么填 |
|------|------|--------|
| 1–3 | 同推荐路线到「已到诊」 | |
| 4 | 临床护理 | **授权出院** |
| 5 | 寄送信件 | **已寄出** |
| — | **终点** | 不进经费、不跑 Java |

## 7. 变更 / 取消线（P11 / P12，可接 P7）

### 入口方式

1. 登记时选 **授权变更 / 随访 / 取消**；或  
2. 主路径预约就诊选 **取消 / 未到诊** 也会进变更。

表单：`clinical_change`（选项会同时决定「去哪」和「要不要财务」）

| 你选的结果 | 去向 `changeTarget` | 是否财务 `moneyAffected` |
|------------|---------------------|---------------------------|
| 授权治疗变更 - 无财务影响 | 治疗 → 经费 | 否 |
| 授权治疗变更 - 需财务复核 | 治疗 → **先 P7 财务调整** → 经费 | 是 |
| 授权随访/改约 - 无财务影响 | 随访 → 回预约就诊 | 否 |
| 授权随访/改约 - 需财务复核 | 随访 → **先财务调整** → 预约 | 是 |
| 授权停止/出院 - 无财务影响 | 出院 → **终点** | 否 |
| 授权停止/出院 - 需财务复核 | 出院 → **先财务调整** → **终点** | 是 |
| 缺少正式临床授权 | invalid | 回补材料 |

### 路线 G — 变更后无财务直接出院

| 顺序 | 任务 | 怎么填 |
|------|------|--------|
| 1 | 登记 | 类型 = **授权变更 / 随访 / 取消** |
| 2 | P11/P12 授权变更 | **授权停止 / 出院 - 无财务影响** |
| — | **终点** `Care episode ended` | |

### 路线 H — 变更 + 财务调整后退款再出院

| 顺序 | 任务 | 表单 | 怎么填 |
|------|------|------|--------|
| 1 | 登记 | `register_request` | 变更 |
| 2 | P11/P12 临床变更 | `clinical_change` | **授权停止 / 出院 - 需财务复核** |
| 3 | P7/P11/P12 财务调整 | `finance_adjustment` | **财务决定已授权且结果已记录** |
| — | **终点** | — | |

## 9. 自测勾选建议（想「全摸一遍」）

按这个顺序各跑一条实例即可覆盖所有终点类型 + Java：

1. **路线 A** — P10 行政问询  
2. **路线 B** — P10 临床问询  
3. **路线 C** — P10 财务问询  
4. **路线 D** — P13 报告  
5. **路线 E** — 转诊驳回  
6. **路线 F** — 转科关闭  
7. **§5 推荐路线** — 主路径 + Java① + Java② + 出院（必做）  
8. **路线 G 或 H** — 变更线到终点  

跑推荐路线时看控制台是否出现：

```text
request-payment SUCCESS ... amount=10.01
send-booking-confirmation ...
```
