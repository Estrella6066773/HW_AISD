## 4. 线 10｜自费完整路径（对着路线自己讲）

病例号 `DEMO-JAVA-01`。Java 要开着。重点：`request-payment`；可选失败支 `mark-payment-investigate`。

```
开始申请 / Start request
  → P1 登记　【选】新转诊 - 材料已核验 / New referral - documents checked
  → P2 转诊　【选】接受 / Accept
  → P3/P4 预约　【选】已预约、通知且已到诊 / Booked, notified and attended
       ← B：check-slot（自动）
  → ★ P5 临床　【选】授权治疗 / Authorise treatment / next cycle
  → P9 寄信　【选】已批准信件已寄出 / Approved letter sent and recorded
  → ★ P7 经费　【选】需要患者付费 - 调用支付方 / Patient payment required
                【填】金额 = 10.01（成功）或 10.00（失败演示）
  → ★ Send Task「发出支付请求」← Java ① request-payment（发布 payment-result）
  → Message Catch「收到支付结果」
       · 10.01 成功 → 继续治疗预约
       · 10.00 失败 → ★ Mark payment investigate ← Java mark-payment-investigate
                      → P7 Funding issue（人工）→ 再评经费
  → P6 治疗预约　【选】资源可用；预约已确认
       ← B：reserve-appointment（自动）
  → Send Task「发送预约确认」← Java ② send-booking-confirmation（B）
  → ★ P5 第二次　【选】授权出院 / Authorise discharge
  → P9 寄信　【选】已批准信件已寄出
  → 【终点】本段诊疗结束 / Care episode ended
```

成功日志：`request-payment SUCCESS ... publishing payment-result`，然后 `send-booking-confirmation SENT ...`  
失败（10.00）额外：`mark-payment-investigate case=... status=INVESTIGATE ...`

### Java（付款）

Open `HospitalPathwayWorkers.requestPayment`. A worker is the Java method Camunda calls. The job type must be `request-payment`. `autoComplete = false` means: publish the message first, then complete the task. If we only complete it, the catch keeps waiting.

打开 `HospitalPathwayWorkers.requestPayment`。Worker 就是 Camunda 来调用的 Java 方法。任务类型必须是 `request-payment`。`autoComplete = false` 的意思是：先发消息，再完成任务。只完成、不发消息，捕获事件会一直等。

The message name is `payment-result`. The correlation key is the case ID. Amount text ending in `0` fails, so `10.00` fails and `10.01` succeeds. If `payment_requested_once` is already true, reuse the old result and do not publish again.

消息名是 `payment-result`。关联键是病例号。金额以 `0` 结尾就失败，所以 `10.00` 失败、`10.01` 成功。如果 `payment_requested_once` 已经是 true，就复用上次结果，不再发消息。

On `10.00`, after the catch, open `RefundWorkers.markPaymentInvestigate`. It does not publish a message. It writes one `payment_ledger` row as `INVESTIGATE`.

金额 `10.00` 时，捕获之后打开 `RefundWorkers.markPaymentInvestigate`。它不发消息，只在 `payment_ledger` 写一行 `INVESTIGATE`。

## 5. 线 13｜变更后退款（对着路线自己讲）

病例号 `DEMO-001`。Java 要开着。表单后自动跑 `request-refund`，写 `payment_ledger`。

```
开始申请 / Start request
  → P1 登记　【选】授权变更 / 随访 / 取消 / Authorised change / follow-up / cancellation
  → P11/P12 变更　【选】授权停止 / 出院 - 需财务复核
                / Authorise stop / discharge - Finance review required
       ← D：notify-care-change（自动）
  → ★ P7 财务调整　form = finance_adjustment
       【选】财务决定已授权且结果已记录 / Financial decision authorised and outcome recorded
  → ★ Service Task「Request refund」← Java request-refund（写 payment_ledger SUCCESSFUL）
       ← 控制台：request-refund case=... decision=resolved status=SUCCESSFUL
  → 【终点】本段诊疗结束 / Care episode ended
```

若选「提供方结果待定 / pending」→ `request-refund` 写 INVESTIGATE，网关回到财务调整重试。

### Java（退款）

Open `RefundWorkers.requestRefund`. This step is not a message. `resolved` writes `payment_ledger` as `SUCCESSFUL`. Anything else, including pending, writes `INVESTIGATE` and the form comes back. The same idempotency key does not insert a second row. The audit actor is `ruby`.

打开 `RefundWorkers.requestRefund`。这一步不是消息。`resolved` 把 `payment_ledger` 写成 `SUCCESSFUL`。其他值，包括 pending，写成 `INVESTIGATE`，表单会回来。同一个幂等键不会插入第二行。审计操作人是 `ruby`。

## 6. 数据库

Two databases. Camunda’s engine database keeps the process: where the token is, and whether the message matched. Our file `data/hospital-domain` keeps the facts. Open `PaymentLedger`: that class is the money table. `request-payment` does not write it. `RefundWorkers` does. `AuditEventWriter` only appends a row. It does not change the old one.

两个库。Camunda 引擎库记流程走到哪、消息对上没有。我们的文件 `data/hospital-domain` 记事实。打开 `PaymentLedger`，这个类就是钱的表。`request-payment` 不写它，`RefundWorkers` 才写。`AuditEventWriter` 只追加一行，不改旧记录。

---

## 7. 收尾

On route 10, `request-payment` must publish the message `payment-result`, or the process keeps waiting. On route 13, `RefundWorkers.requestRefund` only writes the ledger. Route 4 has no worker.

线 10 上，`request-payment` 必须发布消息 `payment-result`，否则流程会一直等。线 13 上，`RefundWorkers.requestRefund` 只写账本。线 4 没有工作器。
