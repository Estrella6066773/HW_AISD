# ruby：案例段落精华

对照：Case Study — Hospital Patient Referral, Treatment and Administration System

---

## 专有名词

| 原文 | 白话 |
|------|------|
| Referral | 转诊：全科医生/别的医院把病人介绍过来 |
| Consultant | 专科顾问医生，临床拍板的人 |
| Medical Secretaries | 医务秘书，收材料、发信，不能看病 |
| Outpatient Bookings | 门诊预约组 |
| Treatment / Chemotherapy Bookings | 治疗/化疗预约组 |
| Call Handling | 电话接线组 |
| CNS | 专科护士，可以给临床建议 |
| Finance | 财务，管钱不管治不治 |
| Pathway Coordinator | 路径协调员，盯有没有拖着 |
| Clinic Letter | 诊后给患者/GP 的正式信件 |
| Audit trail | 谁、什么时候、做了什么，事后能查 |

整篇就一件事：病人从转诊进来，到看病、治疗、付钱、写信、打电话，现在信息太散，医院想做一套系统把流程串起来，并且医生、行政、财务不能互相越权。

---

## 主流程（对应原文段落）

秘书收材料（第3段）  
→ 医生决定收不收（第4段）  
→ 才能约第一次门诊（第4段末、第5段；联系失败/没号见第6段）  
→ 看病后医生授权才能约治疗（第7段、第8段）  
→ 先分清谁出钱、必要时外部支付（第9–13段）  
→ 诊后写信（第19–23段）、接线分流（第16–18段）  
→ 全程留痕（第26–27段）  
→ 医生定医疗、财务定钱、行政只执行（第1段；钱与临床分权见第13–15段、第25段）

补充支线：化疗周期复查（第14段）、正式改期（第15段）、随访预约与爽约（第24–25段）、管理报表与患者沟通偏好（第28–29段）。第30段是对作业组的要求。

---

## 逐段精华

**标题**  
医院患者转诊、治疗与行政系统。

**第1段**  
专科医院管病人从转诊到就诊、诊断、治疗、随访和日常沟通。人很多：秘书、预约、接线、专科护士、治疗预约、路径协调、医生、财务、行政。信息要准、要快，但看病、办事、管钱必须分开。

**第2段**  
现在靠旧系统、电子表、邮件、电话、信和手工本。进度难看、延误难发现、查不清谁做的。所以要上这套系统。

**第3段**  
新转诊先到秘书。秘书只查材料齐不齐（旧信件、检查报告等），缺了可以向转诊方要。秘书不能判断适不适合看、也不能决定收不收。

**第4段**  
材料过了交给医生。医生可以：收、拒、再要材料、转到别的专科。必须记下原因和是谁决定的。只有医生接受后，才能约第一次门诊（New Patient Appointment）。

**第5段**  
接受后，门诊预约组拿到：专科、紧急程度、希望时间、患者特殊需求。用外部排班系统找号，再在本院系统里确认。一般写信通知；如果两周内就要来，还要打电话。

**第6段**  
每次打电话都要记结果：没人接、号码错、患者要改期。还要处理：特别急、等不了普通流程；以及医生要的时间段里根本没号。

**第7段**  
病人来了，医生评估、讲诊断和治疗方案。患者同意后，医生记录同意，并开一张已授权的治疗预约申请（治什么、何时开始、几个周期、中间要不要复查、要什么资源）。没医生签完，行政不能往下办。

**第8段**  
治疗/化疗预约组拿授权单去约。有的用本院，有的靠外面的治疗、化验、影像、排班。外面暂时挂了：预约挂起、通知负责组、记下重试，不要重复建两个号。

**第9段**  
确认治疗预约前，先看钱谁出：医院、保险/资助方、还是患者自己。大多数按规定不用自己掏；自费、海外、可选项目、保险不管的才收费。需要批复时，财务记下：哪家机构、批复号、金额、限制。

**第10段**  
要付钱时，本院系统算出金额，发给外部支付公司。可网上付、或跟有权限的财务打电话付。支付公司回传：成功与否、流水号、日期、金额。本院不能存完整卡号。

**第11段**  
要先付钱的预约：原则上付成功，或有豁免/批复/分期约定后，才能确认。失败、取消、重复、没付完：通知患者和行政。允许再付一次，但不能重复预约，也不能多扣一次钱。

**第12段**  
外面已经扣成功，本院没收到回执（网络断了）：标成「调查」，不要自动再扣一次。病情急、再等有危险：医生可以先治，但必须写原因，事后交给财务处理。

**第13段**  
付完钱后治疗取消/延期/改了：只有有权限的财务决定退全款还是部分退。退款请求发给支付公司，结果记到患者账户。医生可以说明为啥改治疗，一般不能批退款；财务也不能决定临床上要不要治。患者—转诊—治疗申请—预约—资金—支付—退款要能串起来查。

**第14段**  
化疗多周期时，下一周期前可能要复查和验血。能不能继续、要不要推迟、要不要改方案，只有临床能定，预约组和财务不行。

**第15段**  
改已有治疗安排，必须在系统里提交正式的治疗修改申请。只打电话、发邮件、口头说的不算。紧急为了安全可以先停/延，但事后医生必须补授权。改期如果影响已收费或已批复，还要给财务看。

**第16段**  
第一次门诊后，患者会拿到专科护士联系方式，可问病情和治疗。也可以打医院总机。接线组要判断：这是行政问题、钱的问题，还是临床问题。

**第17段**  
接线员可以答简单行政问题（几点、在哪）。钱的问题权限不够就转财务。不能诊断、不能解读化验、不能建议怎么治。临床问题转专科护士或医生。

**第18段**  
每个咨询都要登记：时间、谁接的、分给哪组、回了什么、解决没。紧急临床要马上标出来。但医院还没定完整的“怎样算紧急”，作业里要当成待确认，去问老师。

**第19段**  
每次就诊后医生写诊后信：看了什么、诊断、决定、随访、注意事项。第一封叫 New Patient Clinic Letter。收件人可能是患者、GP、别的医院等，由医生指定。

**第20段**  
信的临床内容医生负责，批准后才能发出。秘书做行政核对、确认收件人、走正规渠道发出。秘书只能改格式类错误，不能改意思；怀疑写错了要退回医生。

**第21段**  
信应在就诊后 7 天内写完、批准、处理、发出，对方大约两周内能收到。系统要记下：就诊日、医生起草/完成日、批准日、秘书处理日、发出日和方式。

**第22段**  
超 7 天没完成/没批准 = 延迟，纳入路径监控。路径协调员每周催医生。超 1 个月升到行政经理；超 3 个月再往上管理层。

**第23段**  
信写完了就别再狂催。允许填写合理延迟原因。催办、回复、升级都要留历史。

**第24段**  
就诊或复查后，医生可申请随访预约，写明应在多久内再看。门诊预约组用外部排班约，并通知患者。临床要的时间里约不到：必须标出来交给路径组，不能偷偷约到窗外假装完成。

**第25段**  
患者可能取消、拒绝或爽约（没来）。要记录，并决定：再约？让临床看路径？通知转诊方？如果是付过钱的，还要问财务：钱留下、转到下次，还是退。行政可以帮忙协调，但能不能继续治、要不要推迟、要不要出院，只有临床能定。

**第26段**  
系统里有隐私：病历、钱。每人只能看自己岗位该看的。要登录、按角色授权、保护对外接口，并记录关键动作（看病历、转诊决定、改预约、临床授权、批信、改治疗、支付、资金、退款）。

**第27段**  
审计记录要有：谁、哪天几点、做了啥，普通人改不了。还要防止不同医院传来的信息把病人配错。系统要尽量一直能用；如果系统或外部服务挂了，线下做的事事后要有补录办法。

**第28段**  
管理层要报表：转诊量、积压、等待时间、电话打不通、信件延迟、咨询没结、治疗约不上、资金批不下来、支付失败、退款卡住、每个人走到哪了。医生嫌记太多耽误看病；管理又要这些数来追责、抓延误。这是冲突。

**第29段**  
患者要及时通知、要隐私。有人要纸质信，有人要电子，有人要无障碍格式、翻译、或让授权代表帮忙。这些期望可能互相打架，各团队现在做法也不统一。

**第30段（对作业组的要求）**  
你们要当需求分析组：找出利益相关者和目标、临床/行政/财务的依赖和冲突、每一步要什么信息和谁授权、怎么跟外部排班/通信/支付打交道、可能怎么失败、提出功能和非功能需求。案例没写清的，标出来，尽量问老师（Tutors），并写下合理假设。
