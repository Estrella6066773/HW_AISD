## 1. 主要业务流程

1. 转诊由 GP / 其他医院进入 → Medical Secretaries 核验材料（可补件，不做临床判断）。  
2. Consultant 审核：接受 / 拒绝 / 补材料 / 转其他专科；记录原因与操作人。  
3. 接受后 Outpatient Bookings 经外部排班约 New Patient Appointment；通常发信，两周内须再电话联系并登记结果。  
4. 就诊后若同意治疗 → Consultant 授权 Treatment Booking Request → Treatment / Chemo Bookings 协调预约。  
5. 确认治疗前判定资金来源；需付款则走外部支付；改期须正式 Modification Request，涉费交 Finance。  
6. 诊后 Clinic Letter：医生撰写批准 → 秘书分发；超时进入提醒与升级。  
7. 患者咨询经 Call Handling 分流（行政 / 财务 / 临床）。

## 2. 主要参与者

| 类别 | 角色 |
|------|------|
| 患者与转诊方 | 患者、GP / 其他医院 |
| 临床 | Consultant、CNS 及相关临床人员 |
| 行政 | Medical Secretaries、Outpatient / Treatment Bookings、Call Handling、Pathway Coordinators、Admin Management |
| 财务 | Finance Team |
| 外部 | 排班、通信、支付、检验/影像等服务方；保险/资助机构 |

职责原则：临床决策、行政执行、财务审批分开，互不越权。

## 3. 关键需求

- 统一支撑转诊→预约→治疗→支付→信件→咨询的路径，替代邮件/电话/手工碎片传递。  
- 关键动作可审计（谁、何时、做了什么），普通用户不可篡改。  
- 按角色控制访问与可执行任务。  
- 对接外部排班、通信、支付等，失败时可挂起、可追踪，避免重复预约/重复扣款。  
- 支持路径监控（积压、延迟信件、未完成支付/咨询等）及管理报表类信息。  
- 沟通渠道与格式需考虑患者偏好（邮寄/电子/无障碍等）。

## 4. 重要业务规则

- 仅授权 Consultant 接受转诊后，方可约新患。  
- 秘书不得决定接受转诊或评估临床适宜性。  
- 无临床授权的治疗请求，行政不得处理；口头/邮件改期无效。  
- 支付不保存完整卡号；预付类预约原则上支付成功（或豁免/批复）后再确认。  
- 支付侧成功但医院无回执 → 标调查，禁止自动再扣。  
- Clinic Letter 须医生批准后才可分发；秘书不得改临床含义。  
- 信件超约 7 天算延迟，并按约 1 月 / 3 月升级催办。  
- Call handler 禁止诊断、解读化验或给出治疗建议。

## 5. 外部服务或组织

- **排班服务**：门诊/治疗等时段查询与占用。  
- **通信服务**：预约信等对外通知。  
- **Payment Service Provider**：收款与退款状态回传。  
- **检验 / 影像 / 外部治疗资源**：治疗预约依赖。  
- **转诊机构、保险/资助方**：来源、补件对象与 funding 批复。
