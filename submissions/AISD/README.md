**Second release, 19 October**: the revised model has now been run on a real engine. `Hospital_All_Processes_V3_C8` was deployed to a local Camunda 8.10.0-alpha5 c8run instance, and the same six acceptance cases that were executed on 29 September were executed again against it, together with a full end-to-end G07 path. G07 reached `COMPLETED` with nine human tasks and no active incident; `AT-01`, `AT-02`, `AT-04`, `AT-05` and `AT-06` pass; **`AT-03` fails** because the model carries no candidate groups, so a Medical Secretary can still complete Consultant Accept and create `BookVisit`. A clean `mvn -B clean test` at `dbc0a33` passes 19 tests ([Java_Clean_Build_Test_2026-10-19.txt](<../../Week3 Coursework/hospital-pathway/evidence/Java_Clean_Build_Test_2026-10-19.txt>)), and the form-binding audit resolves 22 user tasks to 12 distinct form ids with no orphan. The master record is [Camunda_V3_Acceptance_2026-10-19.txt](<../../Week3 Coursework/hospital-pathway/evidence/Camunda_V3_Acceptance_2026-10-19.txt>). The run does not cover browser-side form validation, the role layer, timers (the model has none) or the branches no case drives; see the [written evaluation](<../BPMEA/BPMEA_Written_Evaluation.md>) §4.6.

These files were first uploaded to `main` in `e8a6861`. The 29 September G07 run and its Java logs remain tied to the initial-release source, tagged `submission-2026-09-29` (`f6fec99`); worker source, forms and the executable BPMN have changed since then, so those results describe that tagged baseline rather than the current tree. Neither run proves full acceptance of every business rule or browser-side form validation, and `AT-03` remains a failure in both. Group second-owner review remains open.
