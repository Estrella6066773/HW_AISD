## 内容说明
下表汇总案例研究中描述的所有异常 / 替代路径，以及系统应有的行为。每条均为案例明确提及或可合理推定的异常处理；**未定义规则单独标「待确认」，不写死**（见关键决策第 4 条）。

| 场景 | 替代做法 / 系统应有行为 |
|------|-------------------------|
| 转诊材料缺失 | 标记缺件并向转诊方请求；流程可恢复，不进入"已接受" |
| Consultant 拒绝或转专科 | 记录原因；不启动新患预约 |
| 要求补材料 | 回秘书/转诊方循环，直到可再审 |
| 紧急转诊 | 不按普通行政节奏拖延（加速规则待补全） |
| 时间窗内无号 | 高亮并交 pathway 相关团队，禁止 silently 约到窗外 |
| 两周内电话失败（无人接/错号/要求改期） | 每次尝试与结果入库，可再试或改通知策略 |
| 治疗请求未授权 | 行政侧无法推进 |
| 外部治疗/检验/影像暂不可用 | booking = pending，通知负责团队，防重复建号 |
| 支付失败/取消/未完成 | 通知患者与行政；允许再付；防重复扣款与重复预约 |
| Provider 成功但医院无确认 | 调查状态；禁止自动再扣 |
| 紧急先治后付 | 记录临床原因，转 Finance 事后处理 |
| 取消/改期涉及已付款 | Finance 决定保留/结转/退款 |
| 口头/邮件改期 | 拒绝处理，要求正式 Modification Request |
| 安全原因紧急停/延 | 允许快速操作 + 强制事后授权补录 |
| 改期影响收费或批复 | 必须转 Finance 复核 |
| 化疗前复查不通过 | 仅临床可决定延后或改方案 |
| 信件超 7 天 / 1 月 / 3 月 | 提醒与升级；完成后停止无效催办 |
| 秘书疑临床笔误 | 退回 Consultant，不擅自改含义 |
| DNA / 取消 / 拒绝就诊 | 记录并决策是否再约、是否通知转诊方；涉及费用找 Finance |
| 咨询紧急规则未定 | 先人工标记 + 记 ambiguity，不写死错误规则 |
